# 当前真实状态

> 日期：2026-07-27
> 依据：源代码审查与实际构建结果，不依据旧进展报告。

## 当前可复用

- Tauri 2桌面壳能够在开发模式启动。
- React/Vite/ReactFlow技术栈已安装。
- DeepSeek/MiMo等OpenAI兼容模型调用已有原型。
- SQLite已有原型数据，但Schema会在2.0重构。
- 产品名称、核心定位和设计Token可保留。

## 当前只是原型

- 画布能显示节点，但使用的是“阶段面板”，不是最终任务节点工作区。
- 前端存在传统多页与无限画布两套重复业务流程。
- 前端状态主要依赖组件局部状态与sessionStorage，无法可靠恢复。
- FastAPI启动接口会等待整个调度结束，不是后台运行模型。
- WebSocket只有简单广播，没有持久事件序号与断线补发。
- SQLite把Workflow静态定义与Run运行状态混在一起。

## 当前未真实实现

- Hermes真实异步执行闭环。
- 本机Hermes发现、安装、诊断与健康检查。
- 远程Hermes SSH安装维护。
- 受认证的远程Hermes Node API。
- 多节点能力匹配、负载评分与自动分配。
- 真实取消、暂停、恢复和崩溃恢复。
- 远程文件产出回传、哈希验证及下游路径引用。
- 完整自动化测试、Tauri生产sidecar和可安装DMG验证。

## 已确认的重构目标

- 本地AI执行平台，而非单纯Prompt编排器。
- 本机+多台远程Hermes，由调度器自动分配。
- SSH用于安装维护，受认证API用于日常执行。
- DeepSeek/MiMo独立规划，Hermes只执行。
- 单一无限画布，输入、任务、审核、监控都在一个工作区。
- SQLite存元数据，真实文件保存在项目目录。
- SSH私钥只保存路径。
