# 用户旅程 · 璇玑 App

同一目标在 App 里如何从 0 走到产物。开发调试命令见 [USER_GUIDE.md](USER_GUIDE.md)。

---

## 旅程总览

```text
拿到 DMG
  → 安装并首次放行
  → 配置 Planner + 节点
  → 建项目
  → 生成规划
  → 编辑节点
  → 审核冻结
  → 执行与干预
  → 下载产物
  → （可选）下一轮重规划
```

## 阶段 1 · 安装

| 你 | 系统 |
|----|------|
| 打开 `璇玑_0.3.0_aarch64.dmg` | 挂载磁盘映像 |
| 拖「璇玑.app」到「应用程序」 | 完成安装 |
| 若拦截：系统设置 → 隐私与安全性 → 仍要打开 | ad-hoc 签名下的预期行为 |

**未完成（外部）：** Developer ID 签名、公证、Staple、App Store。

## 阶段 2 · 配置（只需做一次，可随时改）

### Planner

设置中填写 Base URL、Model、API Key。  
用途：画布「生成规划」。Key 写入本地 `credentials.json`（`0600`），接口只回报是否已配置，**不回传**密钥。

### Hermes 节点

| 类型 | 你填什么 |
|------|----------|
| 本机 | API 地址（如 `http://127.0.0.1:8642`）+ Token |
| 远程 | 上述 + SSH Host / Port / User + 本机私钥**路径** + Token |

系统：远程 Node 仅监听对端 `127.0.0.1`；按任务建临时 SSH 隧道（`StrictHostKeyChecking=yes`）。

## 阶段 3 · 建项目

左侧「新项目」→ 系统建 SQLite 元数据 + 项目目录。之后工作流、run、产物都挂此项目。

## 阶段 4 · 规划

画布输入**可验收目标** →「生成规划」→ Planner 出 DAG（非法结构等最多自动修复一次）。

## 阶段 5 · 编辑（审核前）

可改：标题 / 描述 / Prompt、调度与节点约束、超时重试、预期产出、画布位置。  
**审核后全部冻结。**

## 阶段 6 · 审核

通读画布编排 →「审核工作流」→ `reviewed`。  
原则：**思考在先，执行在后** — 审核是硬门。

## 阶段 7 · 执行与干预

「执行全部」→ Coordinator 按依赖调度 → Node → Hermes `/v1/runs`。  
可暂停 / 恢复 / 取消 / 重试 / 跳过。失败不冒充 success。

## 阶段 8 · 产物

检查器下载 → **哈希校验**后写入项目 `root_path`。  
成功 = 真实文件在目录里。

## 失败与重来

| 情况 | 建议 |
|------|------|
| 规划失败 | 查 Planner 配置；改目标再生成 |
| 无在线节点 | 诊断节点 / Token / SSH |
| 单任务失败 | 重试或跳过 |
| 要改已审核图 | 重新规划新版本 |
| 部分失败 | 不能把整次 run 宣传成全成功 |
