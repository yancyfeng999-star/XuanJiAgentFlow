# 产品定义 · 璇玑 App（XuanJiAgentFlowApp）

> **在璇玑玉衡，以齐七政** — 《尚书·舜典》

## 一句话定位

**可安装的本地 AI 任务控制台** — 用户给目标，系统先规划成 DAG，画布上人工审核与编辑，再调度本机 / 多台 Hermes 节点执行，产物回写项目目录。

> 旧表述「有脑子的任务编排器」仍然成立；本文件把落地点钉在 **桌面 App 操作面**，避免与对话 Skill 混谈。

## 核心价值

| 痛点 | App 怎么解 |
|------|------------|
| AI 任务要人盯着聊天窗口 | 独立控制台：规划 → 审核 → 执行 → 产物，可离开对话界面运维 |
| 不知道 AI 在干什么 | 单一无限画布 + 任务状态 + WebSocket 实时推送 |
| 出错无法干预 | 暂停 / 恢复 / 取消 / 重试 / 跳过；审核后冻结防误改 |
| 复杂任务不会拆 | Planner（DeepSeek / MiMo 等）先出 DAG，最多一次自动修复，人再改 |
| 多机与凭据难管 | 节点登记、SSH 隧道、本地 `0600` 凭据，API 不回传密钥 |
| 只要「演示过」的假成功 | 门禁 + 产物哈希；成功 = 真实文件，不靠前端 stub |

## 目标用户

1. **内测 / 本地开发者**：要可装 DMG、可跑 E2E、可挂本机与远程节点  
2. **可视化编排用户**：要看图、改节点、点审核，再执行  
3. **运维向使用者**：管项目库、节点池、历史 run、下载产物  

不主打：完全不懂 Hermes / 节点概念、只想「一句话零配置跑完」的纯小白（那条路径更适合璇玑 Skill）。

## 核心流程

```text
① 安装 App，配置 Planner Key 与 Hermes 节点
    ↓
② 创建项目（目录 + SQLite 元数据）
    ↓
③ 画布输入目标 → 生成规划（DAG）
    ↓
④ 编辑节点（Prompt / 约束 / 重试 / 位置）
    ↓
⑤ 审核工作流（reviewed，冻结）
    ↓
⑥ 执行全部 → Coordinator 调度 → Node Agent → Hermes /v1/runs
    ↓
⑦ 检查器下载产物（哈希校验 → 项目 root_path）
```

## 对标（差异化）

| 产品 | 做了什么 | 相对璇玑 App |
|------|----------|----------------|
| Langflow / Dify / n8n | 可视化工作流 | 璇玑强调 **AI 先规划再人审**，执行面钉 Hermes 节点 |
| Coze 等云端 Bot | 云端编排 | 璇玑 **本地控制台**，密钥不出本机 API 回传 |
| CrewAI 等代码框架 | 多 Agent 代码协作 | 璇玑 **零代码画布** + 可装桌面壳 |
| 纯聊天 Agent | 对话即执行 | 璇玑 App 补 **项目 / 节点 / 产物** 运维面 |

**市场上少有同时钉死这条闭环的本地桌面产品：**

```text
AI 自动规划 → 可视化编辑 → 人工审核冻结 → 多节点真执行 → 产物回写
```
