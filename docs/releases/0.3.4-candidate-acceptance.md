## 2. 新增/修改 API、枚举、事件、持久化字段清单

**API 新增：** `GET /api/readiness`、`POST /api/workflows/{id}/review/prepare`、`POST /api/workflows/{id}/revisions`、`GET /api/projects/{id}/runs`、`POST /api/session/ws-tickets`、`POST /api/nodes/{id}/host-key/inspect`、`POST /api/nodes/{id}/host-key/confirm`。
**API 修改：** `POST /api/workflows/{id}/review` 必须提交 `snapshot_hash`（+警告确认）；`POST /api/workflows/{id}/runs` 与 `POST /api/runs/{id}/start` 增加服务端 Readiness 复检（409 `run_not_ready`）；run 负载新增 `allowed_actions`、`workflow_version`、`review_snapshot_hash`；diagnose 返回分层 `steps`；HTTP 中间件不再接受 `session_token` query 参数；WS 只接受一次性 `ticket`。
**枚举新增：** `TaskStatus.needs_review`、`RunStatus.success_with_warnings`。
**持久化：** schema v3→v4（workflows 审核字段）→v5（tasks 交付合同字段），均 additive；Node Agent task.json 增加 verify/done_definition/verify_results。
**事件：** 无新事件类型；`run.status_changed`/`task.status_changed` 可携带新状态值。

## 3. 迁移与兼容声明

- **schema migration：** v4、v5 均为 additive `ALTER TABLE ... DEFAULT`；升级测试从 v3 手工库验证可读；migration 在事务内执行，失败不会留下半状态（SQLite DDL 事务回滚）；最老支持版本 v1 全链路升级到 v5 由 `test_storage.py` + 新增升级测试覆盖。
- **凭据迁移：** `migrate_credentials` 先写入 Keychain、逐键读回验证、再原子改名旧文件为 `.migrated`（0600）；任何失败保留旧明文文件并返回 `migrated: false`。sidecar 入口（`__main__.py`）使用 `credential_backend="auto"`（macOS 有 `security` 则 Keychain，否则文件）；开发/测试默认 `file`。
- **数据兼容范围：** 0.3.x（schema v1–v3）数据可升级读取；旧客户端打开 v5 数据库会忽略新列（additive），但新状态值（needs_review 等）旧 UI 不识别——不支持降级。
- **中英双语 / 主题：** 全部新 UI 文案均有 zh-CN/en 消息键；亮/暗主题沿用设计令牌（新增 `--warning`）。
- **macOS 最低版本：** 沿用现有配置（macOS 13），本候选未改动部署目标。
