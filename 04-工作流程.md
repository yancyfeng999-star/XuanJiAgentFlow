### 各器交互细节

#### 第1步：输入 → 规划

```
用户输入选题
    │
    ▼
输入器：
  1. 解析选题文本
  2. 检查是否需要补充信息
  3. 组装上下文JSON
    │
    ▼
规划器：
  1. 调用LLM API（OpenAI/Claude）
  2. Prompt = 选题 + 思考框架模板
  3. LLM返回结构化DAG JSON
  4. 验证JSON合法性（节点/依赖/类型）
```

#### 第2步：规划 → 编排

```
规划器输出DAG
    │
    ▼
编排器：
  1. 渲染DAG到ReactFlow画布
  2. 自动布局（层级排列）
  3. 节点按Agent类型着色
  4. 右侧显示AI思考过程
  5. 等待用户操作
    │
    ▼
用户操作循环：
  ┌─ 查看板块 → 点击节点看详情
  ├─ 编辑 → 修改标题/描述/类型
  ├─ 调整 → 拖拽连线改依赖
  ├─ 增删 → 新增/删除任务
  └─ 重拆 → 让AI重新规划某板块
    │
    ▼
用户点击「确认执行」
```

#### 第3步：编排 → 调度 → 执行

```
调度器收到确认后DAG
    │
    ▼
解析依赖：
  level_0: [task_1, task_2]  # 无依赖，可并行
  level_1: [task_3]          # 依赖task_1+task_2
  level_2: [task_4]          # 依赖task_3
    │
    ▼
执行第1轮（并行）：
  调度器 → 执行器 → Hermes API（任务1）
  调度器 → 执行器 → Hermes API（任务2）
    │
    ▼
监视器：实时显示
  ✅ 任务1 完成
  🔄 任务2 运行中...
    │
    ▼
第1轮全部完成 → 收集器暂存产出
    │
    ▼
执行第2轮：
  调度器 → 执行器 → Hermes API（任务3，附带1+2产出）
    │
    ▼
... 重复直到全部完成
    │
    ▼
收集器：汇总所有产出 → 存储器持久化
```

## 流程二：手动执行（导出）

### 完整时序

```
用户          输入器        规划器        编排器        调度器        导出器        收集器
 │              │            │            │            │            │            │
 │──输入选题──→│            │            │            │            │            │
 │              │──上下文───→│            │            │            │            │
 │              │            │──思考拆解──→│            │            │            │
 │              │            │            │──渲染DAG──→│            │            │
 │              │            │            │  等待审核   │            │            │
 │              │            │            │            │            │            │
 │──确认执行───→│            │            │            │            │            │
 │              │            │            │──确认DAG──→│            │            │
 │              │            │            │            │──生成文本──→│            │
 │              │            │            │            │            │──输出prompt─→│
 │              │            │            │            │            │            │
 │←──复制prompt─│            │            │            │            │            │
 │              │            │            │            │            │            │
 │  用户粘贴到Codex/WorkBuddy/其他工具执行               │            │            │
 │              │            │            │            │            │            │
 │──粘贴结果───→│            │            │            │            │            │
 │              │            │            │            │            │──汇总产出──→│
```

### 导出器工作细节

```
调度器触发导出
    │
    ▼
导出器：
  1. 读取DAG结构
  2. 按执行顺序排列任务
  3. 标注依赖关系和并行组
  4. 为每个任务生成独立prompt块：
     ├── Agent类型标注
     ├── 任务目标
     ├── 具体要求
     ├── 前序产出引用
     └── 产出格式约束
  5. 标注可并行执行的任务
  6. 拼接为完整导出文本
```

## 流程三：混合执行

部分任务自动（Hermes），部分任务手动（导出）。

```
调度器根据任务配置决定执行方式：

任务1 → 配置: engine=hermes    → 走执行器
任务2 → 配置: engine=manual    → 走导出器
任务3 → 配置: engine=hermes    → 走执行器
任务4 → 配置: engine=manual    → 走导出器

结果统一由收集器汇总：
  · Hermes任务结果 → 直接获取
  · 手动任务结果 → 用户粘贴提交
```

## 异常处理流程

### 任务失败

```
执行器返回失败
    │
    ▼
调度器判断策略：
  ├── 自动重试（retry_count < max_retries）
  │     └── 重新分发给执行器
  │
  ├── 跳过（用户配置/连续失败）
  │     └── 标记skipped，继续下游
  │
  └── 人工介入（默认）
        └── 监视器弹出提示
              ├── 用户选择：重试
              ├── 用户选择：跳过
              ├── 用户选择：修改后重试
              └── 用户选择：终止整个运行
```

### Hermes不可用

```
执行器调用Hermes API失败
    │
    ▼
调度器：
  1. 标记当前任务为timeout
  2. 暂停依赖该任务的所有下游
  3. 监视器提示用户
  4. 用户可选择：
     ├── 等待Hermes恢复
     ├── 切换为手动执行（导出prompt）
     └── 终止
```

### 部分完成导出

```
用户选择「导出当前可执行任务」
    │
    ▼
导出器：
  1. 只导出 dependencies 全部已完成的任务
  2. 标注「等任务X完成后，执行此任务」
  3. 用户手动执行后，粘贴结果回来
  4. 调度器更新状态，解锁下游任务
```

## 数据流转

```
输入器 ──→ [input_context] ──→ 规划器
规划器 ──→ [dag_v1] ──→ 编排器
编排器 ──→ [dag_confirmed] ──→ 调度器
调度器 ──→ [task_instruction] ──→ 执行器/导出器
执行器 ──→ [task_result] ──→ 调度器
导出器 ──→ [export_text] ──→ 用户
用户 ──→ [manual_result] ──→ 收集器
收集器 ──→ [all_results] ──→ 存储器
存储器 ──→ [持久化] ──→ 历史记录
监视器 ←── [实时状态] ──→ 调度器/执行器
```
